## Live plasma orb

Production orb implementation:

`apps/mom_native/android/app/src/main/kotlin/app/mom/mom_native/PlasmaOrbView.kt`

The implementation uses Matt's supplied native Android plasma code. It continuously redraws using `postInvalidateOnAnimation()` and includes:

- eight primary electrical branches
- randomized path jitter
- randomized surge thickness
- purple blurred outer glow
- thin white electrical core
- four moving edge arcs that can leak just beyond the orb rim

Flutter registration:

`apps/mom_native/android/app/src/main/kotlin/app/mom/mom_native/MainActivity.kt`

Platform-view name:

`mom/plasma_orb`

The MOM home screen hosts it with `AndroidView`.

## Home interface

The orb is intentionally smaller than the earlier full-screen mockup. It is constrained to a square approximately 64% of available phone width, with an upper cap, preserving a circular shape and leaving visual room for MOM's controls.

Startup order:

1. live plasma orb establishes itself
2. microphone is struck into top-left
3. settings is struck into top-right
4. `Version 1.0.1` is struck into bottom-left
5. keyboard/text control is struck into bottom-right

The external strikes use purple glow, a white-hot center, visible travel from the orb rim, and an impact bloom.

MOM's reply caption/history remains beneath the orb. Text input, microphone behavior, settings, and diagnostics callbacks remain wired.

## Settings repair

Previously `_openSettings()` returned immediately when the cloud sync client was null. That made the gear appear dead during sync/bootstrap trouble.

1.0.1 opens local settings whenever local config is available.

Cloud-dependent cross-device identity is disabled only when cloud sync is unavailable. Local settings and save behavior remain usable.

## Build integration

The repository keeps the native Android source under `apps/mom_native/android/`.

The Android workflow generates the Flutter shell, then overlays those native Android files into the generated shell before compiling the APK. This preserves the existing generated-shell build strategy while including `PlasmaOrbView` and the custom `MainActivity` registration.

## Release protection

`tools/verify_mom_1_0_1_ui_contract.py` requires:

- Android `PlasmaOrbView`
- continuous native animation
- Matt's glow/branch/edge-arc behavior
- `mom/plasma_orb` platform-view registration
- compact square orb sizing
- microphone/settings/keyboard controls
- startup control-zap painter
- visible `Version 1.0.1`
- release version `1.0.1+9`

It rejects return of the previous Flutter orb painters and rejects a static image as the production orb path.

## APK rule

Do not build an APK after every small UI edit. The final release APK is built after the feature batch is complete and CI is green.
