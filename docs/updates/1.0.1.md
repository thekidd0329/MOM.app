# MOM 1.0.1

Status: YELLOW — UI + voice update opened

## Release relationship
MOM 1.0.0 is the published baseline. Version 1.0.1 is the first combined production update built from the UI update that began with the canonical trademarked artwork specification.

This update keeps text conversation fully intact. Voice becomes an additional primary conversation path, never a replacement for text. Keyboard/text remains available as fallback and as a deliberate user choice.

## Primary goals
1. Make the production MOM interface match the intended trademarked design instead of the current procedurally painted orb.
2. Restore real audible MOM speech by bringing the verified voice runtime into the production Android path.
3. Preserve the existing text transcript/caption path while voice is added.
4. Continue the Workload 1 conversation engine toward true hands-free use without regressing the UI update.

## Canonical artwork
- Use the exact trademarked `2546.png` artwork as the visual source of truth.
- Do not redraw, regenerate, trace, vectorize, procedurally recreate, or approximate the artwork.
- Do not replace it with a Flutter `CustomPainter` orb.
- Preserve its original plasma structure, pink/violet electricity, bright center, glow, reflection, and overall composition.

## Home screen layout
- Black background in dark mode; white background in light mode.
- Exact `2546.png` centered as the dominant visual.
- Status text centered above the orb, including `Listening...`, `Thinking...`, `Synthesizing...`, `Speaking...`, interrupted/error states, and idle state as appropriate.
- Microphone control: top-left.
- Settings control: top-right.
- Version label: bottom-left.
- Keyboard/text control: bottom-right.

## Signature entrance animation: lightning-zapped controls
The interface should feel as though the plasma orb powers the UI into existence.

1. The exact `2546.png` artwork appears first.
2. Lightning activity builds from the orb.
3. A visible electrical strike travels from the orb toward a control location.
4. The target control flashes into place on impact with a brief glow/bloom.
5. Repeat for the remaining controls and status text in a deliberate sequence.
6. Once the controls are established, the artwork remains the visual anchor and normal MOM interaction begins.

The electrical animation may be layered over the source image, but must never modify or recreate the source artwork itself.

## Visual fidelity vs performance
For 1.0.1, visual fidelity wins. Do not significantly reduce the effect merely to optimize older/slower phones. Full glow, layered strikes, bloom, and timing are allowed even if the entrance animation is heavier on low-end hardware.

## Voice restoration
The 1.0.0 Android baseline can display MOM responses but its published debug APK does not contain the verified CrispASR/Kokoro native runtime. Version 1.0.1 must not repeat that packaging failure.

The production voice path for 1.0.1 is:

`microphone permission → STT → transcript → MOM brain → Kokoro synthesis → device speaker`

Requirements:
- Preserve `input_mode: voice` for speech-originated turns.
- Preserve normal text turns as `input_mode: text`.
- Keep MOM captions/transcript visible whether the answer is spoken or not.
- Keep keyboard/text available at all times as fallback.
- Do not silently swallow synthesis or playback failures.
- Surface voice runtime failures through the voice state/error path and diagnostics.
- Package the ARM64 CrispASR/Kokoro native dependency closure in the final Android build.
- Final APK verification must fail if `libcrispasr.so` or any required staged native runtime library is absent.
- Do not build the final APK until the feature work and integration phases are complete.

## Conversation engine integration
Bring in the completed Workload 1 stages in order, preserving their phase boundaries during development:
- repaired mic-to-speaker contract
- explicit voice state machine: `idle / listening / thinking / synthesizing / speaking / interrupted / error`
- sentence/clause-aware Kokoro chunking with bounded synthesis-ahead memory
- streamed brain output so Kokoro can begin before the full response completes
- user barge-in and immediate playback stop
- interrupted-thought continuity
- MOM redirects when a user is clearly dodging/off-track
- clarification interrupts for unusable STT
- STT timeout/error recovery and speaker/mic coordination
- true hands-free re-listen loop after MOM finishes speaking

## Text stays
Text is a permanent part of MOM 1.0.1.

- Spoken MOM responses continue to produce the same visible caption/transcript.
- Keyboard input remains available from the home screen.
- Voice failures must degrade to usable text instead of making the conversation disappear.
- The UI update must not hide or remove the text path merely because voice becomes primary.

## Current implementation to replace
`apps/mom_native/lib/src/mom_home_screen.dart` currently renders `_ElectricOrb` / `_ElectricOrbPainter` procedurally. That generated orb is not the canonical MOM artwork and should be removed from the production home-screen path once `2546.png` is wired in.

The 1.0.0 Android publishing path also accepted a debug APK without proving the native voice runtime. The 1.0.1 final packaging path must use the stricter runtime verification contract.

## Asset handling
Expected app asset path: `apps/mom_native/assets/ui/2546.png`.

`pubspec.yaml` must register the canonical artwork asset before the new UI is considered complete.

## Release version
Target app version: `1.0.1`.

## 2.0 direction
Later 2.0 work is expected to move the heavier/model-side runtime toward Hugging Face. That future direction is not a reason to simplify the 1.0.1 visual treatment or weaken the 1.0.1 voice path.

## Completion criteria
1. Exact `2546.png` is bundled and displayed in the production app.
2. Procedural fake orb is no longer used for the production MOM home screen.
3. Mic, settings, keyboard, version, and status positions match the intended interface.
4. Controls visibly zap into place from the orb during entrance.
5. Dark and light modes preserve the same trademarked orb artwork.
6. No recreation or alteration of the trademarked source image is introduced.
7. Real voice conversations complete microphone → STT → brain → Kokoro → speaker.
8. Text transcript/captions and keyboard fallback remain available.
9. Voice failures are visible and recoverable instead of silently swallowed.
10. Final Android packaging includes and verifies the required CrispASR/Kokoro ARM64 runtime.
11. Several-minute hands-free conversation succeeds without repeated screen taps.
12. Release metadata reports version `1.0.1`.
